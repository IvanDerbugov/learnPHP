# Куда двигать i-coin до Laravel

Живое приложение сейчас на процедурах: `sendMoney.php`, `getMoney.php`, сессия, PDO. Класс `Account` в `service/Accounts.php` к страницам не подключён: деньги там лежат в памяти, а методы сами печатают HTML. Колонка `isUsualType` в базе есть, наследник `SavingsAccount` на неё не смотрит.

Пароли уже через `password_hash` / `password_verify`, запросы через `prepare`, перевод в транзакции. Это то, что Laravel прячет внутри.

Свой ORM, свой шаблонизатор и свой контейнер зависимостей собирать не нужно.

## 1. Перенос перевода в класс

Один метод вроде `send($pdo, $fromId, $toId, $sum)` забирает транзакцию из `service/methodsMoney/sendMoney.php`: проверка суммы, `beginTransaction`, два `UPDATE`, `commit` / `rollBack`. Скрипт только принимает POST и отдаёт JSON. Класс ничего не печатает и не лезет в `$_POST`.

Так устроены контроллер и модель в Laravel, только без фреймворка.

## 2. Два типа счёта на уже готовой колонке

Обычный и сберегательный класс с общим переводом. Процент начисляет только сберегательный, и только если в строке `isUsualType = 0`. Наследование уже набросано в `service/Accounts.php`, его надо посадить на базу, а не на объекты в памяти.

## 3. Composer и автозагрузка

Один `composer.json` с PSR-4, неймспейс `App\Account`, классы подключаются сами. Сейчас каждый файл начинается с копипасты `error-config.php` и цепочки `require_once`. Без автозагрузки исходники Laravel не читаются.

## 4. Один вход

Сейчас точка входа — каждый `index.php`, `sign-in.php`, `sendMoney.php`. Следующий шаг: один `index.php`, который по адресу вызывает нужный класс. Это уменьшенная копия `public/index.php` и `routes/web.php`.

## 5. История переводов

Таблица `transfers` (`from_id`, `to_id`, `sum`, `created_at`) и `INSERT` в той же транзакции, что и изменение баланса. Сейчас списание есть, а следа «кто кому когда» нет. Заодно это первая миграция руками: отдельный SQL-файл, как потом `php artisan migrate`.

## 6. Настройки снаружи кода

Хост, имя базы, пользователь и пароль — в файле, который не коммитится, или в переменных окружения. Docker потом подставит те же переменные в контейнер.

Docker поднимать на этом же PHP-проекте и только потом переписывать на Laravel. Два прыжка сразу смешивают «не работает контейнер» и «не понимаю фреймворк».

Начинать с пункта 1, на `sendMoney.php`. Когда перевод живёт в классе и скрипт только отвечает JSON, тот же приём переносится на получение денег и на процент по сберегательному счёту.
